# DSH 0.2.2-rc.1 适配与本机验收

2026-11-06：本机宿主已更新至 0.2.2-rc.1，原插件要求 0.2.1-rc.3，安装器在写入前拒绝更新。本次将两个插件的宿主声明、宿主 peer 依赖、本地构建依赖及打包清单统一升级到 0.2.2-rc.1，Cordis 对齐 4.1.0。锁文件重新解析，避免旧虚拟依赖缓存把新宿主与旧版 peer 混合安装。没有添加兼容性豁免，也没有修改业务状态或认证规则。

## 已验证

- Node 25.2.1 下 `pnpm check`：类型检查、构建和全部 114 项测试通过。宿主兼容测试验证新版本无豁免可用、旧版与其他未验版本被拒绝；成对安装测试覆盖版本不匹配时不写入、坏包拒绝及失败回滚。
- `scripts/harness.mjs --install --setup-only` 在独立 `DSH_HOME` 安装两个包，使用官方 0.2.2-rc.1 CLI 启动真实宿主。
- 实际宿主 HTTP：未认证调用 PAP 状态返回 401，认证 owner 可以调用 PAP 状态及 Customer 列表。经真实公网发现文档与 OpenAPI 检查，只导入 a1 的指定咨询资源；随后导入同绑定 JSON 仍只有一项。重启宿主后连接绑定保留。
- 本机现有 desktop Profile 已用官方 CLI 成对更新，两个插件的六个 bundle 与构建逐字节一致。安装前后核对的 59 份账号、连接和历史状态文件摘要未变；其他插件清单、Profile 配置、兼容性文件及工作区配置未变。

## 验证边界

- 真实公网检查与导入没有发送咨询消息、调用付费模型、创建订单或执行支付，也没有登录新的个人账号或发出 PAP 资源令牌。
- 系统屏幕捕获失败，无法完成本轮 Electron 窗口及商家页的交互验收。安装成功不等于当前已打开窗口加载了新 bundle；重新打开 DSH 后仍需核对界面和现有个人连接。
- desktop 原有其他插件仍有其自身的宿主兼容提示；本次保留这些插件和原设置，没有替它们增加版本豁免。
- 安装包仅用于用户授权的本机更新，没有发布 npm、GitHub Release 或公开下载渠道。
