# PAP 独立连接管理

PAP 可在未启用 DSH 账号与 Frontvia Customer 时启动。无客户端身份也能检查/导入服务，但建立连接需要服务接受的正式客户端身份。此变更不发布版本、不修改服务方或身份服务器。

## 依赖与所有权

- PAP → 宿主 Profile、凭据和连接服务。移除 `dsh-identity-client` peer 和 `identity` 强制注入。
- Customer → PAP + 独立账号服务。验证码、登录、退出直接调用账号所有者。
- `customer/src/pap-integration.ts` 注册 DSH 身份授权适配器和 Frontvia 购买证明策略；只接收资源公钥。
- `customer/src/hosted-payment.ts` 校验支付链接与单订单能力，通过 PAP 的受约束辅助请求执行；不发送 PAP 凭据。
- PAP 页面仅管理服务连接。账号变更由 Customer 客户端转换成通用连接失效通知，PAP 不监听 DSH 专属事件或查找商城面板。

## 兼容性

宿主服务 `apiVersion` 升为 2（不是插件发版）。Customer 拒绝旧的 v1 PAP，旧 Customer 也会拒绝 v2，避免只更新一半后错误执行。PAP 页面 RPC 的连接操作保持不变，状态响应移除 `personal`。

SQLite 表结构、加密存储位置、密钥引用、连接 ID 与旧主体不变，无数据库迁移。旧 `personalIdentity` 记录保留，只能由兼容适配器和原账号访问。适配器卸载、账号切换或退出会阻止读取和在途结果；不会删除连接、继承另一账号的连接或自动回退为匿名授权。

已有显式客户端在服务支持 JWT bearer 时继续使用该路径。不同服务或适配器的授权不互相代用。服务链接可以预览任意符合当前 OpenAPI/OpenRPC 发现实现的资源，不再限制为 Frontvia 咨询；预览、用户确认与连接仍是独立步骤。本次不宣称支持所有可能的 PAP API 描述格式。

## 验证范围

运行 `pnpm check`：类型检查、构建、协议与商城回归。新增/迁移的用例验证：

- 无账号服务的真实 PAP 插件入口启动，owner 状态接口与 guest 拒绝。
- 通用服务与不匹配身份适配器共存；连接、读取、重启复用及断开。
- 旧连接经适配器迁移后主体与私钥不变；适配器卸载/恢复、在途卸载拒绝。
- 身份适配器仅接收公钥；未注册证明类型和跨域/凭据辅助请求被拒绝。
- 原账号切换、退出不明、设备密钥丢失、支付链接绑定与购物测试。

浏览器使用本地模拟服务检查页面，不操作真实授权或支付。真实服务商登录/购买、原生 DSH 重启验收、生产部署不由单元测试或浏览器模拟替代。

## 本地安装与回退

1. 构建并通过检查，再制作本地包；组合测试使用相互匹配的 PAP 和 Customer 构建。
2. PAP 单独安装不需要账号包；Frontvia 组合仍需要账号包，不能为满足依赖而删除原账号数据。
3. 本地安装前退出宿主，保留现有 Profile/凭据；新构建不自动转换现有账号连接。
4. 回退时退出宿主，恢复匹配的前一套插件包后重启，继续使用原数据库和凭据。

版本发布、生产部署与服务端配置调整不在本次范围。
